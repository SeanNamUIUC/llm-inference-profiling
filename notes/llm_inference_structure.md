==================================================================
 Transformer 한 층의 계산 과정 + Prefill / Decode 단계별 정리
 기준 모델: Qwen2.5-0.5B-Instruct (24층, hidden size 896)
 예시 문장: "고양이 가 잔다" (토큰 3개)
==================================================================


------------------------------------------------------------------
 1. 896은 무엇인가: hidden size (은닉 차원)
------------------------------------------------------------------

Qwen2.5-0.5B는 토큰 하나를 "숫자 896개짜리 벡터"로 표현한다.

    x(고양이) = [0.12, -0.53, 0.07, ..., 0.08]   <- 숫자 896개

- 모델 설계자가 정한 크기다. 모델이 클수록 커진다.
  (Qwen2.5 기준: 0.5B = 896, 1.5B = 1536, 7B = 3584)
- 896칸 각각은 학습으로 정해진 "특징"이지만, 사람이 읽을 수 있는
  깔끔한 의미는 없다.
- 토큰 3개를 한 줄씩 쌓으면 X = (3 x 896) 행렬
  행 = 토큰, 열 = 896개 특징

가중치 행렬 크기 (GQA 때문에 K, V는 작다):
    W_Q : 896 x 896   (Q 헤드 14개 x 64칸)
    W_K : 896 x 128   (KV 헤드 2개 x 64칸)
    W_V : 896 x 128
    -> K, V를 128칸만 만들어서 KV cache가 작아진다.


------------------------------------------------------------------
 2. Q, K, V를 행렬로 만들기
------------------------------------------------------------------

토큰 하나씩 만들지 않고, 행렬로 한 번에 만든다.

    Q = X . W_Q  ->  (3 x 896)   각 행이 q1(고양이), q2(가), q3(잔다)
    K = X . W_K  ->  (3 x 128)   각 행이 k1, k2, k3
    V = X . W_V  ->  (3 x 128)   각 행이 v1, v2, v3

의미 (이름은 파이썬 딕셔너리에서 왔다):
    q : 이 토큰이 다른 토큰을 "검색할 때" 쓰는 벡터       (검색하는 쪽)
    k : 이 토큰이 "검색당할 때" 비교 대상이 되는 벡터      (검색당하는 쪽의 비교용)
    v : 이 토큰이 검색됐을 때 "실제로 넘겨주는 내용" 벡터  (건네는 내용)


------------------------------------------------------------------
 3. 어텐션 전체 과정 (prefill: 세 토큰 전부를 동시에)
------------------------------------------------------------------

보기 쉽게 벡터를 2칸으로 줄인 손계산 예시:

    q1(고양이)=[1,0]   q2(가)=[0,0]   q3(잔다)=[1,0]
    k1=[2,0]           k2=[0,1]       k3=[2,1]
    v1=[0,1]           v2=[1,0]       v3=[1,1]

[1] 점수표: 모든 q x 모든 k 내적  (행렬로는 Q . K^T)

    검색하는 토큰 \ 대상    고양이(k1)   가(k2)   잔다(k3)
    고양이 (q1)               2           0         2
    가     (q2)               0           0         0
    잔다   (q3)               2           0         2

    (실제로는 sqrt(d)로 나눠서 숫자가 너무 커지지 않게 한다)

[2] causal mask: 미래 토큰은 가리기
    각 토큰은 자기와 앞 토큰만 볼 수 있으니 오른쪽 위를 지운다.

                 고양이   가    잔다
    고양이         2      X      X
    가             0      0      X
    잔다           2      0      2

[3] softmax: 각 행을 합이 1인 비율로

                 고양이   가    잔다
    고양이        1.00   0      0
    가            0.50   0.50   0
    잔다          0.47   0.06   0.47

    -> 이 표가 "누가 누구를 얼마나 참고하나"다.

[4] v 섞기: 각 행의 비율대로 v들을 더하기  (행렬로는 비율표 . V)

    고양이 = 1.00*v1                         = [0, 1]
    가     = 0.50*v1 + 0.50*v2               = [0.5, 0.5]
    잔다   = 0.47*v1 + 0.06*v2 + 0.47*v3     = [0.53, 0.94]

    "v 섞기" = 각 토큰이 참고하기로 한 토큰들의 v를,
               참고하는 비율만큼 더해서 평균 내는 것.
    -> 결과 벡터에 앞 문맥의 정보가 섞여 들어간다.
       고양이: 앞에 아무것도 없으니 자기 v 그대로
       가:     고양이와 자기를 반반
       잔다:   고양이와 자기를 주로 섞음

[5] 뒤에 붙는 두 가지
    - W_O 곱하기: 섞은 결과에 행렬 하나를 더 곱해 896칸으로 정리
    - 잔차 연결: 결과에 원래 x를 더한다 (원래 정보를 잃지 않으려고)


------------------------------------------------------------------
 4. MLP: 토큰마다 혼자 하는 가공
------------------------------------------------------------------

MLP = Multi-Layer Perceptron. 행렬곱 몇 개 + 비선형 함수로 된 작은 신경망.
어텐션 다음에 온다.

    토큰 벡터 (896)
      -> 행렬 곱해서 크게 펼치기 (896 -> 4864)
      -> 비선형 함수 (SwiGLU)
      -> 행렬 곱해서 다시 줄이기 (4864 -> 896)
      -> 원래 벡터에 더하기 (잔차 연결)

어텐션 vs MLP

                  어텐션                     MLP
    하는 일       토큰"끼리" 정보 교환       토큰 "하나씩 따로" 가공
    다른 토큰     봄 (q.k로)                 안 봄
    느낌          "앞에 누가 있었지?" 모으기  "그래서 이건 무슨 뜻이지?" 처리

파라미터 수 (층 하나 기준):
    어텐션 (W_Q + W_K + W_V + W_O)  ~ 180만 개
    MLP    (896 x 4864 x 3)          ~ 1,300만 개   <- 층의 약 88%

    24층 x 약 1,500만 = 약 3.6억
    + 임베딩 표 (151,936 x 896) = 약 1.4억
    = 약 5억 = 0.5B

-> decode에서 매 스텝 읽는 약 1GB의 대부분이 MLP 가중치다.
   양자화로 줄일 때도 MLP를 줄이는 효과가 가장 크다.


------------------------------------------------------------------
 5. 층 하나에서 일어나는 일 (요약)
------------------------------------------------------------------

    X (토큰 수 x 896)
      -> 어텐션: Q,K,V 만들기 -> 점수표 -> 마스크 -> softmax -> v 섞기 -> W_O -> + X
      -> MLP:    896 -> 4864 -> 비선형 -> 896 -> + 입력
      -> 새로운 X (토큰 수 x 896)

    이걸 24번 반복하는 게 모델 전체다.


==================================================================
 6. PREFILL에서 실제로 일어나는 일
==================================================================

입력 "고양이 가 잔다" (3토큰):

[1] 토큰 번호 -> 임베딩 표에서 x 꺼내기
    x1(고양이), x2(가), x3(잔다) -> 한 줄씩 쌓아서 행렬 X (3 x 896)

[2] 1층
    - Q = X.W_Q, K = X.W_K, V = X.W_V   <- 3토큰을 한 번의 행렬곱으로
    - K, V를 KV cache에 저장
    - 어텐션: 위 3장의 [1]~[5]
    - MLP: 위 4장
    -> 새로운 X (3 x 896)

[3] 2층 ~ 24층: [2]를 반복 (층마다 K, V 저장)

[4] 마지막 층 출력 중 "마지막 토큰(잔다)"의 벡터만 꺼내서
    -> 사전 약 15만 개 각각의 점수 계산 -> 제일 높은 것 = 첫 출력 토큰 "."

끝나면 남는 것:
    - 24층 전체의 KV cache (입력 3토큰 분량)
    - 첫 출력 토큰 하나
    max_tokens=1이면 여기서 끝, 그 이상이면 이 KV cache를 들고 decode로.

"병렬로 처리한다"의 의미:
    토큰마다 따로 x1.W_Q, x2.W_Q, x3.W_Q 하지 않고,
    쌓은 행렬 X를 한 번에 곱한다.

    prefill: (토큰 수 x 896) 행렬 . (896 x 896) 행렬   <- 행렬 x 행렬 (GEMM)

면접용 한 문장:
    "prefill은 입력 토큰 전체를 하나의 행렬로 묶어 모든 층을 한 번에
     통과시키면서, 각 층의 K.V를 KV cache에 저장하고 마지막 토큰의
     출력으로 첫 번째 생성 토큰을 만드는 단계입니다."


==================================================================
 7. DECODE에서 실제로 일어나는 일
==================================================================

decode 한 스텝 = 토큰 하나를 만드는 과정. 입력은 직전에 만든 토큰 하나뿐.

[1] 직전 출력 토큰 "." -> 임베딩 표에서 x 꺼내기
    x4(.) -> 1개뿐이라 행렬이 아니라 벡터 (1 x 896)

[2] 1층
    - q4 = x4.W_Q, k4 = x4.W_K, v4 = x4.W_V   <- 벡터 x 행렬 (토큰 1개)
    - k4, v4를 KV cache에 추가 (이제 4토큰 분량)
    - 어텐션: q4와 k1, k2, k3, k4 내적 -> softmax -> v1~v4 섞기
              (k1~k3, v1~v3은 다시 계산하지 않고 KV cache에서 꺼내 씀)
    - MLP: 이 토큰 벡터 하나를 가공
    -> 새로운 x4 (1 x 896)

[3] 2층 ~ 24층: [2]를 반복
    (층마다 그 층의 KV cache를 메모리에서 읽고, k.v 하나씩 추가)

[4] 마지막 층 출력 벡터로 -> 사전 약 15만 개 점수 계산 -> 다음 토큰 t5

[5] t5가 "끝" 토큰이거나 max_tokens에 도달했으면 멈춤
    아니면 t5를 입력으로 [1]부터 다시 (다음 스텝)

스텝 하나에서 읽는 것 vs 계산하는 것:

                  읽는 양                           계산하는 양
    가중치        24층 전체 (약 1GB)                토큰 1개 분량
    KV cache      지금까지 쌓인 모든 토큰의 k, v     q4와 내적 몇 번

    -> 거대한 가중치를 통째로 읽어서 토큰 하나 계산하고 버린다.
       다음 스텝에서 또 통째로 읽는다.
       그래서 연산 장치보다 메모리에서 읽는 속도가 시간을 정한다 = memory-bound.

    decode: (1 x 896) 벡터 . (896 x 896) 행렬   <- 벡터 x 행렬 (GEMV)

면접용 한 문장:
    "decode는 직전에 생성한 토큰 하나를 입력으로 모든 층을 통과시키면서,
     이전 토큰들의 K.V는 KV cache에서 읽어 쓰고 새 토큰의 K.V만 추가해
     다음 토큰을 만드는 과정을 반복하는 단계입니다. 매 스텝 전체 가중치를
     읽지만 계산은 토큰 하나 분량이라 memory-bound입니다."


==================================================================
 8. Prefill vs Decode 비교
==================================================================

                   Prefill                         Decode (한 스텝)
    입력           입력 토큰 전부 (3개, 4096개)    직전 토큰 1개
    핵심 계산      행렬 x 행렬 (GEMM)              벡터 x 행렬 (GEMV)
    KV cache       입력 전체를 새로 만들어 저장     읽어서 쓰고 1토큰분 추가
    가중치 재사용  한 번 읽어 토큰 수천 개에 사용   한 번 읽어 토큰 1개에만 사용
    병목           compute-bound                   memory-bound
    반복           한 번                           출력 토큰 수만큼

핵심: 같은 W를 읽는데, 몇 개 토큰에 재사용하느냐가 둘을 가른다.


==================================================================
 9. 실험 2 (decode 측정)에서 예상되는 것
==================================================================

- 스텝당 시간이 거의 일정할 것: 매 스텝 가중치 약 1GB를 읽는 게
  시간의 대부분이므로.
- 출력이 길어질수록 아주 조금씩 느려질 것: KV cache가 쌓여 읽을 양이
  늘어나므로. 다만 0.5B는 토큰당 약 12KB라 1000토큰이 쌓여도 약 12MB로,
  가중치 1GB에 비하면 거의 티가 안 날 수 있다.
- 큰 모델이나 긴 대화에서는 KV cache 읽기가 커져서
  Residual Quant 같은 KV cache 양자화 연구가 필요해진다.
